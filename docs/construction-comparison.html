Similarities

  • Both build an approximate proximity graph for greedy nearest-neighbour search, and both converge toward the true k-NN graph (watch both recall counters climb).
  • Both exploit that neighbours of neighbours are likely neighbours — merge reuses already-built sub-graph structure via graph search; NN-Descent propagates it across iterations.
  • Both avoid brute-force O(n²) construction and concentrate distance work where it pays off.

Differences

  • Shape of the work: merge = partition → independent sub-builds → hierarchical pairwise stitching (a tree, parallel across partitions). NN-Descent = global synchronous rounds over all nodes.
  • Hierarchy & navigability: merge preserves the HNSW layers and an entry point (navigable). NN-Descent yields a flat k-NN graph — no hierarchy, no designated entry.
  • Connectivity: the flat k-NN graph has no connectivity guarantee — on well-separated clusters it converges to several components (watch the components counter), since each point's true neighbours stay within its own cluster. Merge stays navigable and tends to a single component by stitching across the seam. This is why the NN-Descent panel can look like two separate groups.
  • The seam: merge's hard part is repairing cross-partition connectivity; NN-Descent has no partitions, so no seam, but pays a global iteration cost instead.
  • Incrementality: merge is native to Elasticsearch/Lucene, which builds HNSW per segment and must merge segments; NN-Descent is a from-scratch builder.
